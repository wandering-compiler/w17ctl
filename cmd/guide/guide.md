# AGENTS.md — working in a w17 project (root guide; `w17/AGENTS.md` is the generated symbol map)

You are a coding agent in a **w17 (wandering-compiler)** project. w17 is a declarative
compiler: you declare models, queries, mutations, events and APIs as `.proto` +
`(w17.*)` annotations, and `w17ctl` (a thin client of the w17 console, which does the
compiling) generates the gRPC services, DB layer, SQL migrations, gateways
(REST/SSE/WS/MCP), clients and deploy config. **You hand-write only business handler bodies.**

**Status: alpha (v0).** Any release may carry a breaking fix, so stay current:
`w17ctl update --check`, `w17ctl update --all`, then `w17ctl guide --force` (this file
ships inside w17ctl; `head -1 AGENTS.md` shows the version that wrote it).

## Golden rules

1. **Declare, then generate.** Edit `.proto` under `proto/`, run `w17ctl codegen`.
   Never write DB or gRPC plumbing by hand.
2. **Generated files are DO NOT EDIT** (bundles, pb stubs, clients, migration SQL);
   codegen overwrites them. `grep EDIT-HERE= w17/AGENTS.md` finds the body you own
   (`EDIT-HERE=<file>`); `gen=…` is generated, `none` is plugin-owned (change it via
   the proto's `plugins.features`).
3. **Learn annotations from the tool, not from memory:** `w17ctl template <surface>`
   (`--list`) and the specs below. `w17ctl <command> --help` for any command.
4. **Read an error before repeating a step.** A refusal names its fix; running the
   same command again does not change it.
5. **`push` mints a permanent migration** — it belongs in CI on merge. Your own loop is
   `w17ctl stack build`, which mints nothing.
6. **Call another business method through the registered server**
   (`s.self.Method(ctx, req)`), never as a direct Go call — that skips its events.

## Step 0 — access and login are the human's job

w17 is invitation-only: the human registers at the console from their invitation link
and runs `w17ctl login` (browser or code sign-in, plus 2FA). **You never run `login`**
— you cannot complete it. When a command says you are not logged in, stop and ask the
human to run `w17ctl login` (`--method code` over ssh or in a remote workspace).
`w17ctl whoami` shows who is logged in. CI and deployments never log in; they use a
machine account's `W17_TOKEN` (see `w17/specs/cli.md`).

## The work loop

```
w17ctl guide                               # this file + w17/specs/
w17ctl init --name <project> --go-module <module-path> --stubs-root srcgo/gen \
  --language go --proto-dir proto --languages-dir w17/languages --languages en \
  --e2e yes --ci github --skip-connections [--org <slug>]   # no prompts
w17ctl connection add --name <domain>-postgres --default
w17ctl domain add <domain>                 # --with-example for a sample module
w17ctl module add <domain>/<module>
# edit proto/domains/<domain>/…            (w17ctl template <surface>)
w17ctl codegen                             # generated code + w17/specs + w17/AGENTS.md
# write handler bodies
w17ctl stack build && w17ctl stack up      # local stores; no migration minted
w17ctl test                                # generated e2e suite, throwaway stack
# commit → CI mints the migration (push) and deploys
```

First deploy, CI and `push`: `w17/specs/start-first-deploy.md`. Every command by task
(the cheat-sheet): `w17/specs/cli.md`.

## Finding things in w17/specs — grep, do not read it whole

`w17/specs/` is the platform reference, generated by the compiler and refreshed by
every codegen, so it always matches it. Navigate by topic:

```
grep -i '<keyword>' w17/specs/INDEX.md                 # find topics
w17ctl guide topic <id>                                # print one topic (offline)
w17ctl guide topics <query>                            # the grep above, via w17ctl
sed -n '<first>,<last>p' w17/specs/<file>              # same, without w17ctl
grep -n -A12 '<annotation>' w17/specs/annotations.md   # annotation lookup
```

**First session in a project:** read `w17/specs/start-choosing.md` (language, build
mode, database, deploy target) and `w17/specs/start-layout.md` (domains, modules, what
never to edit) once. `w17/specs/README.md` lists every file. No `w17/specs/` yet? Run
`w17ctl codegen` (or `w17ctl guide --force`); it needs a logged-in console.

## Two AGENTS.md files

- `AGENTS.md` (this file, project root) — how to work. Written by `w17ctl guide`,
  shipped inside w17ctl, refreshed only by `w17ctl guide --force`. `CLAUDE.md`
  imports it with `@AGENTS.md`.
- `w17/AGENTS.md` + `w17/map/` — the generated symbol map of THIS project: grep it to
  find where a thing lives. Every codegen refreshes it.

## Reporting to w17

When w17 is wrong, missing or unclear — a refusal that says "this is a w17 bug", a doc
that does not answer, a feature you need — report it; that is how it gets fixed:
`w17ctl report bug|docs|feature|security --title '<one line>' -F <body.md>`
(`--critical` when it blocks you, `--topic <id>` for docs); `w17ctl report list` follows it.
Tell the human what you sent. What a good report holds, and what is sent: `w17/specs/reporting.md`.
